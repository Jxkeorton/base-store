### Code problems found (fix during the upgrade)

**Security / correctness**
1. `pages/api/checkout_sessions.ts` trusts the price and name sent by the browser. Anyone can buy an item for 1p. Send only `{ id, quantity }` and look the price up server-side from Sanity.
2. `lib/client.ts` passes `NEXT_PUBLIC_SANITY_TOKEN`, so a Sanity token is shipped to every visitor. Remove it. The dataset is public-read, so no token is needed on the client.
3. The Stripe shipping rate ID, the Sanity project ID and the CDN URL string-replace are hardcoded. Move them to env vars and use `urlFor()`.
4. `console.log(req.body)` in the API route and `console.log` of fetched data on the home page.
5. `soldOut` is not enforced at checkout.
6. The success page is not tied to a real session. Verify `session_id` server-side and clear the cart from that.

**Architecture**
7. Pages are `'use client'` and fetch Sanity in `useEffect`. That causes a blank page, a loading flash and no SEO or caching. Convert to Server Components with `fetch` caching and revalidation.
8. The `Pages Router` API route and the `app/` router are mixed. Move to a Route Handler (`app/api/checkout/route.ts`) or a Server Action.
9. The cart is a hand-rolled Context with no persistence, so a refresh empties it.
10. Global CSS (about 600 lines) with a `* { padding:0 }` reset and the `hypik` font declared but not wired through `next/font`. Metadata is placeholder ("Generated by jake") and the favicon path is wrong.
11. Query strings are untyped (`*[_type == "product"]` fetches every field) and types are duplicated in `page.tsx`.

## 2. Brand palette (kept as is)

Extracted from the current CSS:

| Token | Hex | Use |
|---|---|---|
| `--brand` | `#f02d34` | Primary red: CTAs, badges, accents |
| `--brand-deep` | `#e10000` | Hover / pressed |
| `--ink` | `#324d67` | Slate blue: secondary text, headings |
| `--surface` | `#ebebeb` / `#dcdcdc` | Cards and dividers |
| `--text` | `#333` | Body |
| `--paper` | `#fff` | Background |

Generate a tonal scale (50 to 900) for `brand` and `ink` so hover and disabled states do not need ad-hoc hex values. Also verify contrast. White text on `#f02d34` is about 4.2:1, which is fine for large or bold text but needs `--brand-deep` for small text. Add a dark-mode variant only if wanted (optional).

## 3. Phased plan

Each phase is its own branch and PR, deployed to a Vercel preview and checked before merging.

### Phase 0: Safety net (0.5 day)
- Create `upgrade/*` branches and rely on Vercel preview deployments. Do not touch `main` until a phase is approved.
- Record the baseline: `npm run build`, Lighthouse scores, screenshots of every route (home, canopies, used-gear, product, contact, about, success, cart open).
- Remove `dist/` and `.sanity/` from git and add them to `.gitignore`. Drop unused deps (`styled-components`, `@babel/preset-typescript`, `eslint` pin).
- Confirm Vercel env vars: `STRIPE_SECRET_KEY`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`. Add the new ones from phase 2.

### Phase 1: Framework upgrade (1 to 2 days)
Order matters; upgrade in steps and build after each:
1. Next 13.4 to 14 to 15 to 16 using `npx @next/codemod@latest upgrade`. React 18 to 19 comes with it. Fix async `params` in `app/product/[slug]/page.tsx` and replace `next lint` with the ESLint CLI.
2. `next-sanity` 5 to 13, `sanity` 3 to 6, `@sanity/image-url` 1 to 2. Update `sanity.config.ts` and the studio route. Check the Studio at `/studio` still loads.
3. `stripe` 12 to 23 and `@stripe/stripe-js` 1 to 10. Pin the API version explicitly and replace `require('stripe')` with an ES import.
4. `react-icons` 4 to 5, `@vercel/analytics` 1 to 2, `autoprefixer` and `postcss` to current.
5. TypeScript `strict`, remove `any`, drop `@types/stripe-v3` and `@types/react-dom` pin.
6. Set Node 22 LTS in Vercel project settings.

Exit criteria: clean build, no visual change, checkout works in Stripe test mode.

### Phase 2: Architecture and security fixes (2 to 3 days)
- Server Components for home, canopies, used-gear and product pages. Fetch with `sanityFetch` and `revalidate` or tag-based revalidation. Add `generateStaticParams` and `generateMetadata` per product.
- Replace the API route with a Route Handler. Accept `{ id, quantity }[]`, re-fetch price, name, image and `soldOut` from Sanity, create the Stripe session, and read the shipping rate from env.
- Remove the Sanity token from the client. Use a server-only token if a private dataset or draft preview is needed.
- Persist the cart (localStorage via Zustand `persist`, see packages below).
- Verify `session_id` on `/success`. Add a Stripe webhook (`checkout.session.completed`) as the source of truth for orders.
- Add `loading.tsx`, `error.tsx`, `not-found.tsx` and a proper `<Image>` setup (`remotePatterns` for `cdn.sanity.io`).
- Typed GROQ and shared `Product` / `Banner` types (see TypeGen below).

### Phase 3: Design system and Tailwind v4 (1 to 2 days)
- Move to Tailwind v4 (`@import "tailwindcss"` and an `@theme` block holding the palette tokens above).
- Delete the global reset and legacy class-based CSS in `globals.css` as components are migrated.
- Load fonts with `next/font` (one display font for headings, a clean sans for body; keep `hypik` for the logo/wordmark only if it is still wanted).
- Add shadcn/ui primitives (Button, Sheet for the cart and mobile menu, Badge, Card, Skeleton, Sonner toasts).

### Phase 4: Visual redesign (3 to 5 days)
Same red, slate and white palette, with a more modern, editorial outdoor-gear feel.

- **Navbar**: sticky, translucent white with a blur on scroll, a centred or left logo, an underline-on-hover active state, a cart `Sheet` sliding in from the right with a quantity stepper and a subtotal, and a full-screen mobile menu.
- **Hero**: large full-bleed image with a dark gradient overlay for text legibility, a bold headline, one primary red CTA and one outlined secondary. Replace the marquee with a calmer trust strip (UK shipping, tested gear, etc.).
- **Product grid**: a consistent 4:5 image ratio, hover zoom with a second image when available, clear price typography, a "Sold out" badge in slate, quick "Add to bag", 2 columns on mobile, 3 to 4 on desktop, with category filter chips (Canopies / Used gear).
- **Product page**: image gallery with thumbnails and swipe, sticky buy box on desktop, clear stock state, details accordion, and a "You may also like" row.
- **Footer**: slate (`ink`) background with link columns, newsletter slot and payment icons. The existing red footer banner becomes a slimmer CTA band.
- **Cart and checkout**: free-shipping progress or shipping note, empty-cart state, and a nicer `/success` page (order summary pulled from the Stripe session, light confetti kept).
- **Motion and polish**: small fade or slide-in on scroll (Motion), skeletons instead of blank loading, `prefers-reduced-motion` respected.
- **Accessibility and responsive**: contrast pass, focus rings in brand red, 44px touch targets, keyboard-operable cart and menu, tested at 360, 768 and 1280 px.
- Replace the placeholder metadata and favicon, and add OpenGraph images and `sitemap.ts` / `robots.ts`.

### Phase 5: Hardening and launch (1 day)
- Playwright smoke test (home to product to add to cart to Stripe checkout test card), and Vitest for the price lookup and cart reducer.
- Lighthouse targets: Performance 90+, Accessibility 95+, SEO 95+. Compare with the baseline.
- Run the production checkout once with a real small order or in Stripe test mode on the preview, then merge to `main`. Keep the last good deployment ready for instant rollback on Vercel.

## 4. Package suggestions

**Recommended**
| Package | Why |
|---|---|
| `zustand` (with `persist`) | Replaces the Context cart; persisted, tiny, no provider needed |
| `zod` | Validate checkout input and env vars |
| `@t3-oss/env-nextjs` | Type-safe, build-time-checked env vars (catches a missing Stripe key before deploy) |
| `shadcn/ui` (Radix + `class-variance-authority`, `clsx`, `tailwind-merge`) | Accessible Sheet, Dialog, Button, Badge without lock-in |
| `sonner` | Replaces `react-hot-toast`; works with shadcn |
| `lucide-react` | Replaces `react-icons` (smaller bundle, consistent icons) |
| `motion` | Small, tasteful animation |
| `sanity typegen` (built in) or `groqd` | Typed GROQ queries, removes the duplicated interfaces |
| `@sanity/preview-url-secret` + Draft Mode | Live preview of content edits |
| `embla-carousel-react` | Product image gallery / mobile swipe |
| `vitest` + `@playwright/test` | Cart logic and checkout smoke tests |
| `biome` or `eslint` flat config + `prettier` | Fast, consistent linting and formatting |
| `@sentry/nextjs` | Error tracking on checkout |

**Worth considering later**
- Stripe webhooks plus a small order store (Vercel Postgres/Neon with Drizzle, or Supabase) for order history and stock decrements.
- `resend` for order and contact-form emails (the contact page currently has no backend).
- `@vercel/speed-insights` next to the Analytics you already have.
- `next-intl` if you ever sell outside the UK. Today shipping is GB only.
- `@upstash/ratelimit` on the checkout route.

**Remove:** `styled-components`, `@babel/preset-typescript`, `react-hot-toast` (after Sonner), `react-icons` (after Lucide), `@types/stripe-v3`.

## 5. Risks and open questions

1. Sanity v3 to v6 and next-sanity 5 to 13 are the biggest jumps. Do them in isolation and check the Studio and the content schemas.
2. Tailwind v4 changes some default utilities. Visual regression screenshots from phase 0 are the check.
3. The Stripe shipping rate (`shr_...`) is tied to the current Stripe account and mode. Confirm it is the live-mode ID before moving it into an env var.
4. Does the client want stock counts (the `quantity` field exists but is unused) or just sold out / available?
5. Do you want a dark mode, search, or customer accounts? None are in scope here.

## 6. Estimated effort

About 9 to 14 working days in total (phases 0 to 5), shippable after each phase.
